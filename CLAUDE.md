# Cyberpunk TCG Vault: agent notes

React 19 + Vite + TypeScript front end, Supabase (auth + RLS data), and a Vercel function for photo scanning. See `README.md` for setup and architecture.

## Checks

Run `npm run check` (lint + tests + typecheck/build) before committing. Tests live next to their code (`*.test.ts`, Vitest).

## Data

- `src/data/*.json`, `api/_cards.ts` and `api/_carddata.ts` are generated by `scripts/sync-data.mjs` (the daily GitHub Action; `_carddata.ts` via `scripts/gen-api-data.mjs`). Don't hand-edit them.
- Pricing logic lives in `src/lib/data.ts` and `src/lib/pricebook.ts` (selectors). Keep them pure and tested. Holdings use `valueHolding(printingId)` (Market, Beta proxy for verified pairs only, Low listing, else null). Anything you'd buy uses `acquireQuote(slug)` via `purchaseEstimate` in `src/lib/decks.ts` (direct quotes on a named printing; never proxies). Unknown prices are `null`, never 0: show "Unpriced" or a partial total (`estimateText`). Feed matching rules live in `scripts/price-build.mjs` (tested in `src/lib/pricing.test.ts`).
- Amounts are computed internally in CAD. Display them only through `money()` from `src/lib/currency.ts`, which follows the USD/CAD toggle (default USD). Never format prices by hand or hardcode a currency label; use `getCurrency()`.
- **Hand-curated data** (edit these, not `src/data/`):
  - `src/curated/card-ratings.json`: power (1-10) + roles for every playable card. Drives the auto-builder.
  - `src/curated/starter-decks.json`: the physical retail starter lists (official WeirdCo decklists) with Retail and Beta printing IDs. Separate from the demo collection. `src/lib/starters.test.ts` checks every printing exists and both decks are legal.
  - `scripts/deck_notes.json` + `scripts/decks_src.py`: recommended deck lists and write-ups. Run `python3 scripts/decks_src.py` to validate and regenerate `src/data/decks.json`.
- Every holding has an explicit printing. Copies whose printing isn't known are stored as `unspecified:<slug>` (`unspecifiedId`, `normalizePrinting` in `src/lib/data.ts`): they count for deck building but are unpriced. Imports with unknown printing ids become unspecified, never guessed. Copies change printing only via `movePrinting` in the store (cloud: the `move_copies` RPC, migration 004, which refuses stale moves).
- `addMany` in the store is all-or-nothing and resolves `false` on a failed save; callers must check it before reporting success.
- Deck rules live in `src/lib/decks.ts` (`validate`, `completion`). The auto-builder (`src/lib/autobuild.ts`) is deterministic and must only return decks that pass `validate`.
- The upgrade planner (`src/lib/upgrade.ts`) shares `cardScore`, `synergy`, `compositionPenalty` and `scoreDeck` with the auto-builder, keeps Legends fixed, and must only return decks that pass `validate`. Budgets are in the display currency; costs stay internal CAD and are compared with `toDisplay`. Unpriced purchases are never added and never confirmed as within budget. Decks move between screens via `src/lib/handoff.ts`; the planner never writes the collection or saved decks.
- Deck sharing (`src/lib/share.ts`, `ShareDialog`, `views/SharedDeck.tsx`, migration 005): links snapshot the deck as stored on the server, so the builder saves first and only publishes after `saveDeck` resolves true. One share per deck; replace rotates the token, revoke deletes it. The only public read is `get_shared_deck(token)`, which returns an allowlist: never add owner ids, notes or collection data to it. The reader sanitizes snapshots (`sanitizeShared`) and compares locally (`compareDeck`): "To play it" is Legends + main, the sideboard is a separate line, owned copies count once. `/d/<token>` is `api/share-preview.ts` (OG tags, then redirect to `#/shared?deck=`).
- Test hand / Compare hands (`src/lib/handtest.ts`, `components/HandTester.tsx`): browser-only, works on snapshots of the lists it's given and never writes decks or the collection. Setup follows the official guide (main deck only, draw 6, one full-hand mulligan). `deckStats` is the single source for curve, average cost, Unit and sellable counts (the Deck Builder uses it too). "Opening hand odds" are exact hypergeometric (`atLeastOne`), never estimated from sample hands. Trials take an injected RNG (`seeded`) so tests are deterministic.
- Saved decks are owner-only: load them with explicit columns and a `user_id` filter, never `select('*')`.
- Serverless functions can't import app modules at runtime, so `api/_deckrules.ts` mirrors those rules for the server. `api/_deckrules.test.ts` checks the two agree; change both together.
- AI deck refinement (`api/refine-deck.ts`): the model only proposes. Code repairs its list to owned, RAM-legal cards and re-validates before returning; prices never come from the model. Usage is capped per user per day (`ai_usage`, `DECK_DAILY_LIMIT`) and site-wide (`api/_aiguard.ts`, `ai_global_usage`), with `UNLIMITED_EMAILS` as an env-only bypass. Any new AI endpoint must go through `takeGlobal`. Never hardcode emails or keys; the repo is public.
- Schema changes go in a new numbered file in `supabase/migrations/` and are also appended to `supabase/schema.sql`.

## Design

**Read `docs/design-system.md` before changing any UI.** It defines the Afterlife design language, the core rules, tokens, type roles, component patterns and responsive behaviour.

- Tokens live in `src/theme.css`. Use semantic tokens (`--color-*`, `--font-*`, `--space-*`, `--cut-*`); never hardcode hex values in components.
- Build screens from the shared pieces: `Masthead`, `MetricStrip`, `ConfirmDialog` (`src/components/ui.tsx`) and the classes in `src/styles.css`.
- The Price Book (`src/views/PriceBook.tsx`, `src/views/pricebook.css`) is the reference implementation.
- Destructive actions go through `ConfirmDialog` (see `DeleteCollection.tsx`).
- Avoid em-dashes in UI copy.
- Before calling UI work done: check laptop and phone widths, long names, missing art, loading/empty states and keyboard focus.
